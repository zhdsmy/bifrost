# Bifrost v0.2.8

Bifrost is an unofficial Tailscale plugin for the KoolCenter / Koolshare software center. It is not affiliated with, endorsed by, or sponsored by Tailscale Inc.

## Added

- Request Previous Tags: a login after a logout can keep the device's tags.
  - Logging out records the device's tags and the control server that gave them.
  - The login card and the Re-authenticate confirmation have a Request Previous Tags checkbox. It shows when the device has tags and is checked by default.
  - When checked, the login requests the tags again with `--advertise-tags`, only from the control server that gave them. The account that logs in must own them (`tagOwners`).
  - When cleared, the login requests no tags, and the router becomes a device of the account that logs in, as in v0.2.7.
- When the control server refuses the tags, the page says so and asks to clear the checkbox and try again.
  - An interactive login whose tags are refused can only time out. The expiry notice then mentions the tags.
- A login that succeeds without the requested tags shows a warning instead of the success message. The warning asks to set the tags in the admin console or to use a tagged auth key.

## Changed

- Page contract: `login` takes a third parameter and `relogin` one parameter, whether to request the previous tags. The status file has `self.tags` and `saved_tags`. The login job data has `tags` and `tags_applied`.
- The fallback of Connect for a stopped device mentions the profile's advertised tags, so Tailscale's check for unmentioned settings accepts it.

## headscale and auth keys

headscale 0.29.7 gives no tags to a user's pre-auth key:

- A new device, or a device tagged at registration, is refused. The page shows the refusal.
- A device registered with that user's key and tagged later by an admin logs in without the tags. The page shows the warning.

Use a tagged auth key with headscale, or set the tags again after the login.

## Included core

- Unchanged: Tailscale core `v1.104.7`, published as `core-1.104.7-2`.
- Packages: `hnd` and `hnd-arm64` carry the uncompressed core (the default). `hnd-upx` and `hnd-arm64-upx` carry a UPX core. Pick the package with the core type you use: an offline package replaces an installed core with the same serial.

## Tested hardware and firmware

ASUS RT-AX86U running Asuswrt-Merlin `388.12_2`, with the core on USB storage (ext4), and an `hnd` package built locally from the same code as this release (only the version number differs):

- The offline upgrade from v0.2.7 restarted the daemon once. The daemon came back running with no health warnings.
- A logout and an interactive login with Request Previous Tags, on the Tailscale control server, authorized by scanning the QR code. The router kept its tag and its key expiry stayed disabled. The advertised route, accepted routes, and tailnet address were the same as before the logout.
- The page was checked in Chrome on the router: the login card and the Re-authenticate confirmation with the checkbox, in dark and light mode, and in English.

The container integration tests run against headscale 0.29.7 and the real core. They cover the tags saved at logout, an interactive login by the tag owner that keeps them, an auth key login that loses them (reported), and an auth key login that is refused.

## Not tested

- The warning for tags the control server did not grant, on hardware. It was seen with headscale only.
- A refused tag request on the Tailscale control server.
- The ISP's weekly PPPoE redial and a router reboot with v0.2.1 or later.
- `arm64` packages on hardware.
