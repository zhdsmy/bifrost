# Bifrost v0.2.5

Bifrost is an unofficial Tailscale plugin for the KoolCenter / Koolshare software center. It is not affiliated with, endorsed by, or sponsored by Tailscale Inc.

## Added

- Core tab: the previous core backup shows its version, type, architecture, and size, and has a Delete button. The rollback confirmation names the version it restores.
- Core tab: the tab shows where the core is stored (router internal flash, external USB storage, or unknown, with the filesystem type) and the free space there.
- Core tab: the expected SHA-256 from the signed core manifest is shown under the hash command, and the arm64 switch explains when it helps.

## Changed

- Update checks and core downloads use the GitHub API (`api.github.com` and its file CDN) before `github.com`, which is often slow or blocked in some networks.
  - A download mirror, when set, is still tried first. It now falls back to GitHub when it fails.
  - The API allows 60 unauthenticated requests an hour per IP address. A check or an update uses about five. When the limit is reached, `github.com` is used.
  - Signatures and hashes are checked as before.
- The previous core is no longer kept on internal flash (jffs2, ubifs, yaffs, or an mtd/ubi device). Internal flash is small and shared with the firmware and other plugins.
  - A failed update still restores the current core automatically. Only the manual rollback is unavailable there.
  - Upgrading the plugin removes a previous core that an older release left on internal flash.
- On other storage, the previous core is kept only when the free space left afterwards still holds one more copy of the current core (the next update unpacks beside it) plus 2 MB, the minimum the software center requires for upgrades.
- The UPX hint on the Core tab depends on the storage. On jffs2 or ubifs, the filesystem already compresses the uncompressed core, so UPX saves less than the file sizes suggest. On external storage, UPX is not needed to save space.
- Core tab layout: Update Core is the main button only when a newer core is known, and it is disabled when the last check found the core up to date. The type and architecture switches have their own group. Field pairs are tidier, and the list of omitted features is folded.
- Core tab values (architecture, core type, filesystem, previous backup) are plain text instead of badges. Outline badges (header version, advertised routes, path, omitted features) use the same border as secondary buttons, so they stay visible in dark and light mode.
- Sizes use decimal units (1 MB = 1,000,000 bytes), as in the docs. They used 1024-based values with MB and GB labels before.

## Fixed

- The Core tab no longer says that reinstalling the plugin package restores a missing previous core. A package with an older core does not replace a newer installed core.
- Updating when the channel offers the installed core now reports "already up to date" (`up_to_date`) instead of `old_serial`, which said the channel core was older.

## Included core

- Unchanged: Tailscale core `v1.104.7`, published as `core-1.104.7-2`.
- Packages: `hnd` and `hnd-arm64` carry the uncompressed core (the default). `hnd-upx` and `hnd-arm64-upx` carry a UPX core. Pick the package with the core type you use: an offline package replaces an installed core with the same serial.

## Tested hardware and firmware

ASUS RT-AX86U running Asuswrt-Merlin `388.12_2`, with the core on USB storage (ext4), and an `hnd` package built locally from the same code as this release:

- The offline upgrade from the v0.2.4 release package restarted the daemon once. The daemon came back with the same devices, the status check passed, and the previous core backup was kept.
- The router page file points to the new page assets, and the old assets were removed.
- An update check finished in 6 seconds. A traced download of the core manifest, its signature, and the 9.6 MB core used only the GitHub API (5 requests) and took 6 seconds. The core hash matched the manifest.
- Update Core, with the installed core on the channel, reported "already up to date".
- The Core tab and the badge borders were checked in the local preview in dark and light mode. They were not checked in a browser on the router page.

## Not tested

- `arm64` packages on hardware.
- The internal flash rule on hardware: the test router keeps the core on USB storage. Shell tests cover it.
- Rollback and Delete of the previous core from the page on hardware.
- The fallback from the GitHub API to `github.com` (API limit reached or API blocked) on hardware. Shell tests cover it.

## Verify downloaded files

Download `SHA256SUMS`, `SHA256SUMS.sig`, and the public key from `plugin/bifrost/keys/` at this release tag. Verify the signature first, then the package hash. The checksums and commands follow at the end of these notes.
